# P2-WP04：知识工具进入同一受控模型链路

基于WP03，按持续授权自动实施。目标是材料快照、两个当前事实和示例知识在同一证据包中呈现，模型摘要附可验证原文引用；不进入P3记忆或风险研判。

- [x] 新增固定第三工具query_knowledge，参数仅question且必须对应入口明确的knowledge_question。复用KnowledgeStore SQL过滤；工具错误保留，不提供身份/索引/写入参数，不建通用注册平台。
- [x] 扩展现有循环为可选三工具：默认原两工具不变。知识问题明确提供时必须观察第三工具；材料与查询结果仍是数据，不得改权限。默认3模型回合/4动作/75秒限制保留。
- [x] 最终摘要分离工具事实，新增knowledge_citations（chunk_id与quote），验证chunk来自本轮知识观察、quote为返回片段原文；无知识结果时不得伪造引用。结构/引用有效不等于语义正确，摘要仍为unverified_candidate。
- [x] CLI在check-facts-agent增加--knowledge-question，默认协议替身；知识入口复用本地编码/PG，不改材料状态。真实调用使用同一生产账本、工作包P2-WP04，不能沿用WP02包额度。
- [x] 先红后绿：三工具观察/停止，参数身份注入拒绝，伪造chunk/quote拒绝，无结果/工具失败保留，两工具旧回归不退化。
- [x] 3个已见合成整合任务（正常、过期事实、知识无结果）各最多3请求，包上限10，累计从6/100续算；先替身后真实，失败保留，逐例人工核对候选摘要但不冒称专家/本人验收。
- [x] 独立规格/代码审查、必要PG与P1回归、状态/矩阵/学习/handoff更新后，进入WP05本地追踪平台与P2 Gate。

安全与来源边界：query_knowledge仅查询授权示例知识，不解释成企业合规依据；知识引用只证明与返回原文一致，相关性/充足性另评估。不产生批准、报警控制或真实业务副作用。
