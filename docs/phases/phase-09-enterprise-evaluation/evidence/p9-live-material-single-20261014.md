# 单案例真实 DeepSeek 离线评测

日期：2026-10-14。该实验用于演示评测实施方法，不用于证明模型可靠性或企业效果。

## 评测定义

- 模式：`model_in_loop_predeployment_demo`；固定合成输入，调用线上 `deepseek-flash`，不是生产流量评测。
- 输入：四个材料字段均非空，作业位置为“SYNTHETIC：到装置边上操作”。
- 预期：`work_location_description / ambiguous`；模型应要求补充具体区域和作业点。
- 自动评分：比较 `(field, kind)` 集合，计算 exact match、TP、FP、FN。
- 人工复核：检查引用是否来自输入、追问是否能补齐信息、是否出现批准或安全结论。

## 实际结果

- 模型：`deepseek-flash`；Prompt：`materials-v2`；语义状态：`checked`。
- 输出：识别 `work_location_description / ambiguous`，引用“到装置边上操作”，追问“请说明具体区域与作业点。”
- 自动评分：exact match=true，TP=1，FP=0，FN=0。
- 人工复核：本例通过；追问与缺失信息对应，没有自动批准或安全结论。
- 用量：478 token；端到端约3146.16ms。

## 保留的实现问题与限制

首次临时 PowerShell 评分使用嵌套数组时发生自动展开，存在把两个字符串分别比较而产生假阳性的风险。未再次请求模型；改用 Python 元组集合重新评分并覆盖本地派生分数，原模型结果不变。这说明评分器本身也必须测试，不能只相信最终绿色数字。

本例与历史地点含糊案例相似，运行后也是开发者已见案例。它只证明当前版本在这一个输入上返回了预期结果。没有覆盖其他措辞、错误确定性、工具/RAG、多轮恢复或真实安全管理人员评价。

请求后只读预算快照为总计64/100、P8-WP04为8/10。本轮只明确归因本次1个成功请求；上次状态57/100之后的其他新增尝试未在本实验中归因。
