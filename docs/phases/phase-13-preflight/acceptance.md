## G2 自动预核查与完成门控

- [ ] 首次提交/重提持久化唯一自动任务；刷新、重复确认不重复提交或启动工具。
- [ ] 合法对象绑定后执行三项只读查询，知识问题基于本轮作业而非固定告警问题。
- [ ] 查询outcome与业务状态分离：active/正常/有效来源、异常、缺失和错误均有明确状态。
- [ ] 知识候选有当前引用；完成时人工确认适用引用，不能传任意引用或客户端ready绕过。
- [ ] 只在当前完整且无未解决异常的依据及人工确认下允许完成；不是正式审批/开工授权。
- [ ] 缺口/失败不阻止查看、提出补充或源修复后重查；仅改绑定/仅源更新也有合法重提路径。
- [ ] 改材料/换人换区域/来源换版撤回/有效期到期/撤权使旧依据过时，不能沿用旧卡片。
- [ ] 查询I/O不占长事务；结果回写与完成使用正确任务锁，竞争和旧轮次回写均拒绝。
- [ ] 排队任务/执行尝试/结果可跨实际进程恢复，原结果与审计保留，无隐式付费重试。

## G3 双角色交互与事件复核

- [ ] 两不同身份/私聊共享同申请及预核查投影；待办包含状态，错误展示不伪装成功。
- [ ] 能查看对象、版本、来源/时间、知识引用、缺口/异常、人工确认和重查入口。
- [ ] 作业中事件使用本申请绑定，而非服务器固定worker/area；旧绑定事件核查标过时。
- [ ] 预核查异常不吞原始报警、不自动清警；缺少可靠依据时保持人工核实边界。
- [ ] 演示先作业前查询再材料完成，再合成事件；不声称真实平台/正式许可或自动销票。
