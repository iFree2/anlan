## 发布前备份

1. 备份当前应用目录、服务配置、环境文件和静态 MCP/知识夹具；权限保持原样，凭据不打印、不入库。
2. 用 PG 原生备份创建可恢复数据库快照，记录当前迁移号、关键表行数、旧额度审计行指纹及原角色令牌数量。不要输出 DSN 或凭证。
3. 记录当前 release、systemd 单元、监听地址和健康响应；旧 release 与数据库备份使用独立不可覆盖路径。
4. 确认 017/018/012 和现有 audit-only 策略保持；只应用从 SQL019 开始的新迁移。

## 维护切换

1. 进入维护页或停止新写入，等待现有业务事务结束；不中断仍处于合法短租约内的只读预核查任务。
2. 备份后原子切换新 release，启动一个实例执行增量迁移和健康检查。
3. 核对 `/healthz`、带认证的 `/readyz`、旧行数/摘要、迁移版本、角色授权和目录可见性。
4. 用两个不同身份做只读冒烟：同申请共享、预核查对象/版本/来源可见、私聊不可见、旧完成卡片仍只读。
5. 恢复写入前确认新提交必须已绑定，完成必须使用当前 check 与人工选定引用。

## 模型与权限

- 默认保持 SYNTHETIC、scripted/offline；真实模型不是 P13 预核查必要条件。
- 任何真实模型验证需新的明确授权、有效预算账本和有限样本，不重置/扩大历史限额。
- 企业 MCP、真实企业目录和现场设备未接入。目录仍来自受信配置并与事实 ACL 相交。

## 失败与恢复

- 新应用启动失败：保持维护态，保留备份与失败日志，修复后前向恢复。
- 不切回可绕过预核查的旧写 API；旧代码只能作为历史制品保存。
- queued/running 预核查使用 PG lease 和 attempt 审计；过期租约可由新进程恢复，只读查询不自动产生付费模型重试。
- 回写旧轮次、失效来源、过期引用和换绑定事件必须拒绝 current；原始报警不能因应用故障被删除或自动清警。
- 回滚以恢复已验证的新门控版本或维护应用为限；恢复旧数据库会丢失新审计并让旧版本绕过门控，禁止。
