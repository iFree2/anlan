## 首包 P3-WP01

只处理SYNTHETIC的呈现偏好/复核反馈，不保存人员当前资质、区域“安全”结论、批准或告警控制意图。优先以明确的结构化合成反馈生成candidate，再由模拟可信用户确认active；不把Codex对话里的长期编码授权当成应用记忆数据，也不让模型直接修改权限或记忆生命周期。

建议单一小模块与PG迁移，记录memory_id、tenant/user、类型/键/值、source_ref、source_hash、created_at/updated_at/expires_at、revision和状态。字段/值先用少量有业务意义的白名单（例如呈现详略），不做通用记忆平台。source_ref应关联确有归属的任务/run或版本化合成反馈，不能伪造来源存在。

提供CLI或现有服务入口，演示candidate→确认/拒绝→修正/冲突→过期/删除，默认读取仅active且未过期、本用户可访问的记录。旧版本/重复提交行为明确；修正与删除不能被旧候选/旧请求静默复活。删除可用tombstone保留合成审计，但不得宣称生产隐私合规。时间可注入，错误不改已有状态。

首包先AI实现并验证，不追加真实模型请求。保留P1恢复/P2工具、知识与预算回归；更新status/矩阵/学习/交接后自动进入下一包，不再等待常规“继续”。具体接口和小步骤由新任务读现有代码后落实，沿用同目录，不重建PG或模型适配。
