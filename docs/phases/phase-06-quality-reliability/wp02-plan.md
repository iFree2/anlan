# P6-WP02：反馈、Badcase与录制回放

顺序接续WP01后执行；沿用用户长期授权。Goal：用已有合成感知记录形成可核对的反馈→Badcase→归因→改动→回归闭环，不引入业务自动决策或另一份预算权威。

## 设计

采用小型离线评测模块与命令，复用P5/P6已落盘的合成实验工件。来源路径、SHA、review/run、feedback来源与结构/应用状态明确；原failed无原输出时只能标记不可完整回放，不能伪造修复后的历史输出。真实反馈仍来自原PG，导出是已记录的合成回放操作者，不冒称人类反馈。只接受显式选定的SYNTHETIC工件，不扫描任意用户文件。

三层入口：inspect只读摘要；replay把记录中的可用候选和上下文交给当前验证器，不导入HTTP/模型客户端或查询新事实；rerun明确是已有受预算控制的evaluate_perception命令，默认关闭，不从replay隐式触发。录制回放只能测验证器变化，不能代替真实模型重新生成。

先冻结开发与留出清单及同源分组。开发包含两条旧失败/修订后同源记录，留出采用另外构造的完整未知、材料缺项、引用错配、禁止指令等合成合同案例；相同source/family不得跨分割。留出为AI构造、事先冻结但非独立人类金标；打开结果后即已见，不继续调参再冒称盲测。

分类只表示可观测失败层（解析、引用、未知、反馈争议等）；缺证据时根因unknown。WP01合同改动作为第一项改进，原模型0/2与新实验并列；离线回放不能证明模型收益。SQL归因汇总与有限Judge另在WP03/04实现。
