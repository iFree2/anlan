# 安澜2.0项目说明

安澜2.0是面向高风险作业安全协同的个人Agent工程实践。以动火作业为主线，将材料补充、当前事实与示例制度、待人工复核候选、模拟事件重核和反馈回放串起来。使用Python/LangGraph、PostgreSQL/pgvector、少量Java只读API与MCP、FastAPI/SSE；工程由AI协作实现，全部业务记录明确为SYNTHETIC。

项目不自动批准作业、不控制/关闭原始报警。它要解决的是“材料和证据怎样可恢复、可追溯地交给人复核”，不是替代安全管理人员或建设完整审批/IoT平台。[产品范围](../../product-scope.md)

## 演示入口与证据

按[主链演示](takeover-demo.md)使用新目录运行固定零模型命令。演示覆盖材料3轮、两类事件的真实本地事实/知识查询、替身候选/合成反馈、材料变更使旧候选stale、冻结Badcase回放。不同演示段的任务身份分开，历史质量数据不会被说成本次自动挖掘结果。

| 可以展示的工程结果 | 证据与实际边界 |
|---|---|
| 任务恢复、幂等和隔离 | PG持久归属/operation/checkpoint，锁与写连接一致；不保证外部模型exactly-once |
| 工具/知识/偏好 | 当前事实经只读工具查询；知识带版本/时效/来源；记忆只含两种呈现偏好 |
| 事件与服务 | 两类模拟原报警、来源绑定、重核/反馈、显式修订；本地HTTP/SSE与清洁wheel有历史实测 |
| 质量闭环 | 重复unknown Badcase复现→归因→长度校验→回归；独立合同留出首次5/5，非模型泛化集 |
| 接管与拓展 | 进程树/源码绑定修复，Mem0静态比较，一个受限空间合成资料任务，有限合成图片API实验 |

实验都为小型已见/合成数据，不报告泛化准确率、线上A/B收益或生产SLA。[完整限制](known-limitations.md)、[质量项](../../quality-items.md)
