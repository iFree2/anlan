# 半年路线图

## 持续执行约定（2026-09-20更新）

用户已授权后续任务自动执行到底，以最终成果验收。各包先实现并亲自运行必要验证，保留失败/退化，更新status、能力矩阵、学习记录与handoff，再自动开始下一包；常规设计选择、已有范围确认或练习答案不再是暂停点。旧计划中的“等待确认后实现”是历史协作约定，当前以本条为准。

只在明显范围变化、破坏性操作、真实业务副作用、缺少关键输入或用量预算耗尽时暂停依赖部分，提出具体问题一次并记入status；独立工作继续。用户后续“长期授权你全力推进”已由协调任务同步；采用已告知用户的保守执行上限：每包10次、新授权后累计100次真实模型请求，失败也计数。这不是金额预算或无限付费授权；只用既定供应商/模型与合成数据，调用前可靠预占且跨进程/子任务共享账本，P1历史三次单独保留。替身与真实结果始终分开；个人掌握默认待验，AI交付不升级个人能力，不虚构企业经验或实验收益。

各阶段仍需工程Gate；通过后在同一项目目录新建下一阶段GPT-6 Astra/high任务，以仓库handoff冷启动。新任务提示必须包含持续执行授权，不能沿用旧版“先等确认再实现”。协调任务已有每30分钟检查的自动续接（automation id=2-0），仅在空闲时续接，不与运行中的阶段任务并行修改代码，不创建重复自动化。

26 周 × 15—20 小时，约 390—520 小时。阶段通常 2—4 周；当前只细化最初两周，后续安排是可据实修订的容量分配。原 JD 的关键能力争取约 70%—80% 的**可验证学习覆盖目标**，不宣称已达比例，不等于岗位匹配或招聘概率。原文、通用补充、实施证据与个人掌握分别记录在[能力矩阵](capability-matrix.md)；该矩阵是本路线图的唯一能力表，避免复制两份。

| 阶段 | 周 | 业务交付与学习重心 | 退出证据 | 状态 |
|---|---|---|---|---|
| P1 多轮工作流 | 1—2 | 材料 → 追问 → 补充 → 再分析；真实模型小样本；PostgreSQL 恢复 | CLI 全路径、重启/隔离/故障、冻结工程回归；个人记录独立 | 工程Gate通过；个人掌握/语义泛化待验 |
| P2 工具与知识 | 3—6 | 合成事实 Python 工具、有界工具循环、示例知识摄取与 pgvector RAG；接追踪平台（优先评估Langfuse） | 越权/超时、时效/撤回；检索与依据支持分开评测 | WP01—WP03通过；推进知识工具整合/追踪，阶段未完成 |
| P3 Memory 与 Context | 7—10 | 跨会话偏好/反馈候选、来源与生命周期；上下文预算与 Skill | 无/有记忆、纠正冲突/删除隔离、上下文消融；形成单 Agent 综合研判基线 | 未开始 |
| P4 作业前多 Agent | 11—14 | 11—12 周先拆知识/事实并行；13—14 周加风险、证据复核、受限协调；Java 少量 API/MCP | 并行汇合、超时、部分失败、取消、父子预算、冲突；初次单/多 Agent 对照 | 未开始 |
| P5 感知协同与服务 | 15—18 | 模拟视频/传感器事件、关联去重、条件变更重核、感知 Agent；FastAPI/SSE、Compose/CI | 两类事件与人工反馈回放；报警不依赖 Agent；断连/恢复、清洁环境启动 | 未开始 |
| P6 质量与可靠性 | 19—22 | 减少功能；反馈→Badcase→归因→改进→回归；只读回放/录制回放/复跑；SQL/语义分析 | 留出集、校准 Judge、单/多 Agent 复测及证据复核消融、故障与性能实验 | 未开始 |
| P7 接管与求职 | 23—26 | 有限离线多模态；Mem0/Letta 择一比较；小型受限空间复用；本人独立排错、讲解和面试 | 对照数据、失败复盘、可复现演示、如实简历、个人掌握证据 | 未开始 |

预算不足时优先保证 P1—P6 主线及本人接管；缩小多模态样本与第二任务，不砍权限/隔离/失败处理。知识图谱、GraphRAG、A2A、训练、微调、大规模推理和 K8s 按需了解；AgentScope/Dify/ADK 仅选型比较，不逐个重做。观测选一种平台，Redis/队列/MQTT 必须有并发或解耦证据才引入。

## 各阶段个人掌握清单

2026-09-20按用户最新要求：开发持续按工作包推进，AI先运行并记录工程验证；以下要求先列出，个人证据随后补齐。未完成练习不阻塞后续编码，不因AI完成实现而标记本人掌握。阶段切换检查工程验收和个人记录，二者分别报告。详细来源、深度、实施证据和实际掌握状态仍只在[能力矩阵](capability-matrix.md)维护，下面是各阶段的阅读/实践重点。

| 阶段 | 需要理解并逐步能独立完成的内容 | 最小个人实践方向 |
|---|---|---|
| P1 多轮工作流 | TypedDict与Pydantic；Graph节点/条件边/interrupt重入；字段合并与revision；task/thread/run/tenant；checkpoint/幂等恢复；模型结构与语义区别 | 跑通并讲解一次跨进程补充，修改一个节点或定位一次输入/恢复问题 |
| P2 工具与知识 | Tool参数/结果/错误契约；模型→工具→观察→停止循环；最小权限/超时；知识切分/版本/租户与有效期过滤；检索命中和引用支持；追踪定位 | 修改一个真实合成查询工具，定位一次检索错因或工具失败，比较一个检索改进 |
| P3 Memory/Context | 状态、知识、偏好与情景记忆的区别；候选写入/检索/更新/压缩/过期/删除/冲突；上下文预算与裁剪；Prompt/Skill/工具/工作流边界 | 修改记忆筛选或上下文策略，用有/无记忆或消融结果解释收益与损害 |
| P4 多Agent | 拆分理由和独立上下文；角色输入输出及工具白名单；并行汇合；父子预算/超时/取消/部分失败；冲突汇总；单/多Agent对照 | 定位一次子任务失败或冲突，解释一次拆分的效果、费用和延迟取舍 |
| P5 感知与服务 | 事件身份/时序/关联/去重/乱序；原始报警与Agent推断边界；条件变更重核；FastAPI/SSE与断连；配置迁移、Compose和基础CI | 复现错误事件关联或重复事件，用一次服务部署演示状态恢复 |
| P6 质量闭环 | 指标与开发/留出；过程约束与最终效果；Judge校准；只读查看/录制回放/重新调用区分；SQL/语义Badcase分析；故障和延迟测量 | 独立完成一次Badcase→归因→改动→回归，保留无改善/退化数据并解释 |
| P7 接管与求职 | 自有Memory与一种开源实现取舍；有限多模态质量/延迟/费用对比；资产复用边界；设计讲解与排错；个人实践与企业生产经验区分 | 独立演示主链、现场修改/排错，讲清实验与不足，形成真实项目说明 |

每个工作包结束时，只列本包3—5个理解问题和一个可选小练习，不要求一次掌握整阶段全部内容。本人练习/解释证据写入learning-log；AI测试通过单独记录为工程证据。

每个工作包按 [status](status.md) 冷启动：适用 AGENTS、状态、阶段计划、最近 handoff、相关 ADR、Git 状态/最近提交、最小 smoke。Phase Gate 单独检查完整路径、冻结评测和失败、个人掌握、过期文档、阶段 handoff；过关后同目录新建 GPT-6 Astra / high 任务，启动提示依据用户原始约定和仓库事实重建。
