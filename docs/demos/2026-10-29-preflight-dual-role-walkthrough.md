# 安澜 P13 双角色作业前依据闭环演练

本演练使用 SYNTHETIC 人员、区域、事实和知识。材料核查完成不等于正式审批、作业许可或开工授权。不要使用真实企业资料，也不要把演示令牌写入仓库。

## 启动

```powershell
. .\scripts\dev-postgres.ps1 -Action Env
.\.venv\Scripts\python.exe scripts\prepare_collaboration_demo.py --output .runtime\p13-demo-<新目录>
```

如知识库尚未准备，先按该目录的 `service.json` 租户和两份角色身份，将公开合成知识摄入独立本地 PG。启动服务时只把共同 `service.json` 交给后端；申请人窗口选择 `applicant.json`，安全人员窗口选择 `safety-manager.json`。

```powershell
.\.venv\Scripts\python.exe -m anlan.interfaces.serve `
  --config .runtime\p13-demo-<新目录>\service.json --port 8017
```

打开两个隔离浏览器上下文：`http://127.0.0.1:8017/console`。页面只把令牌保存在当前页面内存。

## 正常依据

1. 申请人新建会话，输入完整动火材料：合成台架、试件、焊接方式和附件说明，并确认创建。
2. 在“作业前依据”选择 `SYNTHETIC 正常作业人员`、`SYNTHETIC 焊接资质`、`SYNTHETIC 正常区域`，确认本申请对象。
3. 对话输入“提交申请给 safety-manager-demo”，核对冻结版本后确认。
4. 两侧刷新。依据应显示当前对象、材料/绑定/check 版本、固定查询时间、来源观察/有效期和三项结果；知识只作为待人工确认候选。

## 异常与补充

1. 新建另一项申请，选择 `SYNTHETIC 资质异常人员` 与 `SYNTHETIC 受限区域`，提交给安全人员。
2. 安全人员应看到 `suspended`、`restricted` 和明确缺口，不能看到可绕过的完成按钮。
3. 安全人员填写补充要求并确认；申请人刷新后看到最新状态和完整要求。
4. 申请人换为正常人员/正常区域，确认绑定；随后重提申请。仅改绑定也必须允许重提，且旧依据应显示过时。
5. 等待新预核查 ready。安全人员勾选本轮实际采用的知识引用、填写人工结论，生成并核对新卡片后确认。
6. 申请状态应变为“材料核查完成”，显示采用了哪个 check、哪个绑定及哪些引用；不得显示“已批准”或“允许开工”。

## 作业中事件

1. 安全人员在“事件、核查与反馈详情”中生成一个合成气体异常事件。
2. 确认原始报警保持 `active`；事件详情使用当前申请绑定，而不是 `console_profiles` 中的固定人员/区域。
3. 发起核查后应看到三项查询结果和人工反馈入口。反馈不会自动清警或改变作业许可。
4. 若在核查后换绑定，旧事件核查应变为 `stale_binding`，但保留历史记录和原始报警。

## 排障

- 目录为空：检查租户、identity 和 `preflight_catalogs`；不要在页面手工填 ID。
- 预核查一直过时：刷新确认材料/绑定/申请版本，必要时显式重查；不要通过改无关文字伪造新版本。
- 事件 409：事件绑定版本可能已过期，按当前申请重新生成事件。
- 完成按钮不出现：确认当前身份为安全人员、依据 ready、存在当前引用，并已通过结构化渠道选择引用。
- 重启后保留原数据库和任务；“恢复”不应重复提交、重复查询或伪造依据。
