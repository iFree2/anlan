# 模型调用只记账、不设项目次数上限

用户2026-10-25明确要求“不要有额度限制”，取代当前线上100累计、30对话和10材料事件的限额策略。范围仅取消安澜当前线上授权的累计/分包次数拦截；不是取消供应商余额/限流，也不授权代理额外付费自测或无限自动重试。保留每次调用记录、原失败、原授权/分包历史数值、超时、单次循环/并发边界和身份授权。不修复未授权的模型格式/通用提示/确认路由功能。

推荐独立SQL018策略表：默认启用限额；管理员对现用authorization显式设置limits_enforced=false。普通新授权仍保持限额，现有账本/授权行不被改写。reserve仍持久化预占与结果、策略读取与预占共用授权锁，只在限额启用时检查计数。没有策略行即保持旧行为；数据库不可用仍拒绝请求，不旁路审计。

不采用删除账本（丢审计）或调大数值（仍有上限）。模型info对当前策略返回audit_only和null有效上限/剩余，同时展示已用次数；保留账本历史配置但明确它们不是当前有效上限。策略仅DB管理通道修改，不给浏览器接口。前端显示项目次数不限，不误称供应商免费。

先真实本地PG RED/GREEN，覆盖额度用尽后显式关闭仍能记账、旧记录与初始化/重连/并发保持、默认限额及HTTP信息。构建新wheel/离源码检查；云端备份DB/配置及发布路径，维护停机后增量SQL018并设置唯一现用授权策略，再启动新版。旧业务/全部调用记录保持，0真实供应商验证，不代用户重发未提交申请。维护回滚不恢复DB；前向恢复固定新制品。供应商故障与模型输出失败仍可能出现。
